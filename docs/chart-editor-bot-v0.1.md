# ТЗ: FNF Chart Editor — Telegram-бот, v0.1

## 1. Общее

- Продукт: редактор чартов для Friday Night Funkin' в виде Telegram-бота **@FNFsongBotCRT_bot**.
- Этот этап — чистый бот с inline-кнопками. Telegram Mini App (WebApp, экран 1280×720) — следующий этап; ядро редактора (модель данных, логика) не должно зависеть от интерфейса.
- Стек — на усмотрение разработчика (рекомендация: Python + aiogram 3.x или Node.js + grammY).

## 2. Безопасность

- Токен бота хранится ТОЛЬКО в переменной окружения `TELEGRAM_BOT_TOKEN` (допустим файл `.env`).
- `.env` добавлен в `.gitignore` первым же коммитом. Токен не должен попадать в репозиторий, issues и документацию ни в каком виде.
- Токен передаётся разработчику лично, вне GitHub.

## 3. Сценарий использования

1. `/start` → приветствие + кнопка «🎼 Новый чарт».
2. «Новый чарт» → бот отправляет **сообщение-редактор** и далее только редактирует его (`editMessageText`), не отправляя новых сообщений на каждый тап.
3. Пользователь расставляет ноты кнопками, «✅ Готово» завершает сессию.

## 4. Сообщение-редактор

Поле выводится моноширинным код-блоком:

```
 ←  ↓  ↑  →
 ·  ·  ·  ·
 *  ·  ·  ·
 ·  ·  *  ·
▶·  *  ·  ·
────────────
Строка 4 / 4
⏱ 00:00.750
```

- Пустая ячейка — `·`, нота — `*`.
- Текущая строка помечена `▶` в начале.
- Показывается окно из максимум 15 строк вокруг курсора (лимит Telegram — 4096 символов на сообщение); общий размер виден в строке «Строка N / M».
- Таймер = `row * stepMs`, формат `MM:SS.mmm`.

## 5. Inline-кнопки

| Ряд | Кнопки | Действие |
|---|---|---|
| 1 | `←` `↓` `↑` `→` | Toggle ноты в текущей строке: тап ставит `*`, повторный тап убирает. Несколько нот в строке = аккорд. |
| 2 | `▲ Назад` `▼ Далее` | Перемещение курсора на строку вверх/вниз. `▼ Далее` на последней строке создаёт новую. `▲ Назад` на строке 0 — ничего не делает. |
| 3 | `🗑 Строка` `✅ Готово` | Очистить текущую строку / завершить редактирование. |

- На каждый тап — `answerCallbackQuery` без текста (чтобы кнопка не «зависала»).
- «✅ Готово» → бот присылает итоговое сообщение: полный чарт (при необходимости в несколько сообщений) и статистику (строк, нот).

## 6. Модель данных

Чарт — структура данных; текстовое поле — лишь её отображение.

```
Chart {
  stepMs: 250          // длительность строки; параметр, не константа
  rows:   int          // общее число строк
  notes:  [{row: int, lane: int}]   // lane: 0=←, 1=↓, 2=↑, 3=→
}
```

- Отрисовка — чистая функция `render(chart, cursorRow) -> text`.
- `stepMs = 250` по умолчанию (1/4 бита при 120 BPM).
- Это ядро позже без изменений используется в Mini App и в экспорте в формат FNF (JSON, `sectionNotes`).

## 7. Сессии и хранение

- Одна активная сессия редактирования на пользователя (ключ — user id).
- Повторный «Новый чарт» при активной сессии — запрос подтверждения перед сбросом.
- Хранение — в памяти процесса. Персистентность (файл/БД) — v0.2.
